# 数据类型与误差

## Scratch 只有双精度

Scratch 里所有数字都是 IEEE 754 双精度浮点数（double），没有整数类型。
双精度有 53 位有效二进制位，约等于十进制 15–17 位有效数字。

- 能表示的最大值约 $1.798\times10^{308}$；
- 最小正规数约 $2.2\times10^{-308}$，再往下是次正规数，到 $10^{-323}$ 左右；
- 超出范围就是 `Infinity`，无意义运算得到 `NaN`（SGC 里显示为 `?`）。

## 经典的反例

$$2^{100}+1-2^{100}$$

数学上是 1，但在双精度下：

```text
2^100          = 1.2676506002282294e+30
2^100 + 1      = 1.2676506002282294e+30
2^100 + 1 - 2^100 = 0
```

原因很直接：$2^{100}$ 的量级是 $10^{30}$，而双精度在这个量级上的间隔远大于 1，
加 1 直接被舍入掉了。

## 这对使用意味着什么

1. **大数相减会掉精度**。`(10^20+1)-(10^20)` 得不到 1。
2. **判断相等要小心**。`a == b` 对浮点结果常常不成立，比较时留一个容差更稳。
3. **`NaN` 会传染**。任何数与 `NaN` 运算都得 `NaN`；`1/0` 在 SGC 里也是 `NaN`。
4. **坐标太大时图形会抖**。像素坐标和世界坐标换算时，量级差太大就会损失细节。

## SGC 的处理

- 内部一律按 double 存，不区分 int / float；
- `NaN` 统一显示成 `?`，避免看起来像正常数字；
- 隐函数、函数图像用**区块加载**：只算当前视口附近的格子，避免一次算几百万个点；
- 结果超出范围时宁可显示 `Infinity`，也不悄悄截断。

!!! note "和 CAS 的区别"
    symPy、Mathematica 这类 CAS 会用大整数和有理数保存精确值，`2^100+1-2^100` 就是 1。
    SGC 不做这件事——它要的是能在 Scratch 的 500ms 里跑完的速度。
